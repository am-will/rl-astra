# Ball physics comparison

Checkpoint before this work: `4936d96`.

Reference: [RocketSim c2baacb8f4b441dd8505e63c2aeb5a1679b60b02](https://github.com/ZealanL/RocketSim/tree/c2baacb8f4b441dd8505e63c2aeb5a1679b60b02), compiled locally in Release mode. These measurements use the actual reference library, not a second JavaScript implementation of its formulas.

## What changed

- Ball collision radius: 0.92 → 0.9125 (91.25 Unreal units).
- Ball/arena restitution: 0.585 effective → 0.6.
- Ball/arena friction: 0.5 floor / 0.475 wall → 0.35.
- Ball/car restitution: 0.315 effective → 0.
- Ball/car friction: 0.225 → 2.
- Drag: replace Rapier damping 0.045 with Bullet's `(1 - 0.03)^dt` applied before gravity/contacts. Remove angular damping 0.13; retain the 6 rad/s cap.
- Replace the base kick, unconditional upward impulse and gentle-hit scaling with RocketSim's relative-speed curve and direction adjustment. The extra impulse uses incoming states for both cars, rather than feeding one car's bonus into the other car's calculation.
- Allow an extra impulse every other physics tick during contact, independently of the existing 180 ms sound/visual event cooldown. Serialize the physics cooldown with car state.
- Remove the bespoke restoration of the striking car's lost forward velocity.

Gravity (6.5), mass (30), speed cap (60), and 120 Hz timestep already matched. The car driving model and chassis collision shape remain as before.

Rapier's installed JavaScript API does not expose solver-material modification hooks. Two coincident sphere colliders on the same ball body provide separate car and arena materials. Their collision masks are mutually exclusive; only one collider can resolve any given pair. The second collider has zero mass, preserving the sphere's mass and inertia. Both handles are restored in multiplayer checkpoints. Wheel queries recognize either sphere. Chassis/arena and car/car material settings are preserved.

## Measurements

Values below are in game world units (100 Unreal units). Y is up. The reference harness rotates coordinates without reflection so angular velocity and tangential friction use the same handedness.

| Check | Measured difference from RocketSim |
|---|---|
| Extra-hit formula, 21 speed/angle cases | Maximum vector error < 0.00001 |
| Drops from center heights 2 / 5 / 10 | First rebound heights about 0.55% / 0.43% / 0.25% lower |
| Free flight after 1 second | Velocity error < 0.0001; position difference about 0.024 |
| Spin in free flight | No difference in the tested case |
| Angled floor impacts, zero spin and ±4 rad/s | Velocity-vector difference < 0.104; spin-vector difference < 0.033 rad/s |

Representative grounded shots use a settled, forward-facing car, a stationary ball, throttle held, and boost at the highest speed. The reference uses its standard Octane; our car uses our existing chassis, center of mass, suspension, and driving model. Thus these are comparisons of the complete approach and strike, not identical incoming collision states.

## Scope and remaining differences

This is close ball-model alignment, not full engine parity. Rapier and RocketSim's modified Bullet differ in integration, contact timing, friction solving, and penetration correction. RocketSim also merges ball/world contacts into a special averaged contact; Rapier uses its own manifold solver. Our arena ramps and goal geometry are generated meshes rather than Rocket League's extracted collision meshes.

Complete car strikes still differ: the slowest tested approach produces about 25% extra forward speed; the boosted shot produces about 14% less lift. The other tested lift differences are under 6%. The remaining differences should be investigated through matched incoming contact states and car geometry/inertia before introducing any empirical hit multipliers. No per-speed corrective tuning was added.

The reference harness uses an empty RocketSim arena with a flat plane and standard soccar ball materials. It needs no proprietary meshes. Its floor data do not establish parity for corners, goal posts, or ramps.

## Reproducing the comparison

The checked-in JSON fixture is generated by `tests/reference/rocketsim-ball.cpp` against the pinned upstream revision. Free-fall cases start with a negligible downward velocity because RocketSim explicitly sleeps a ball with exactly zero velocity even when placed in midair.

```sh
git clone https://github.com/ZealanL/RocketSim.git /tmp/rl-astra-rocketsim-reference
git -C /tmp/rl-astra-rocketsim-reference checkout c2baacb8f4b441dd8505e63c2aeb5a1679b60b02
cmake -S /tmp/rl-astra-rocketsim-reference -B /tmp/rl-astra-rocketsim-reference/build -DCMAKE_BUILD_TYPE=Release
cmake --build /tmp/rl-astra-rocketsim-reference/build -j 8
g++ -std=c++20 -O2 -I /tmp/rl-astra-rocketsim-reference tests/reference/rocketsim-ball.cpp /tmp/rl-astra-rocketsim-reference/build/libRocketSim.a -o /tmp/rl-astra-rocketsim-ball
/tmp/rl-astra-rocketsim-ball > tests/reference/rocketsim-ball.json
npm run test:ball-physics
```

The normal test uses the checked-in fixture and requires no C++ dependency. Its report is written to `test-results/ball-physics/comparison.json`. It also verifies actual contact materials, wall/ceiling collision routing, sphere inertia, and deterministic restoration during car touches. Historical tests expecting only a tiny reduction from the original custom bounce have been replaced by these reference-based expectations.
